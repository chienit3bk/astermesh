# Privacy, Data Protection, and Intellectual Property Compliance

## 1. Scope and Regulatory Alignment

This document specifies the data protection architecture, privacy-by-design controls, and intellectual property compliance of **Astermesh** for global users and contributors, in strict accordance with:

- **Vietnam Law on Personal Data Protection No. 91/2025/QH15** and **Decree No. 13/2023/ND-CP** on the Protection of Personal Data.
- **Vietnam Law on Intellectual Property** (consolidated through **Law No. 131/2025/QH15**) and **Decree No. 17/2023/ND-CP**.
- **Vietnam Law on Artificial Intelligence No. 134/2025/QH15**.
- International privacy and open-source governance frameworks, including the **EU General Data Protection Regulation (GDPR)**.

---

## 2. Zero Personal Data Collection and Local-Only Processing

- **100% Local Execution**: Astermesh parses abstract syntax trees (`tree-sitter`) and constructs code knowledge graphs (`networkx`, `igraph`, `leidenalg`) exclusively in local memory (`RAM`) on the user's host machine.
- **No Telemetry, Analytics, or Cloud Uploads**: Astermesh contains zero telemetry hooks, analytics trackers, crash reporters, or remote API calls. It never collects, stores, or transmits Basic Personal Data or Sensitive Personal Data to any external server.
- **No Cross-Border Data Transfers**: Because the core indexing engine and Model Context Protocol (`MCP`) server run strictly locally (`stdio` or local loopback `127.0.0.1` by default), no source code, repository metadata, or personal data is transferred across national borders by Astermesh.
- **Strict Workspace Boundary Isolation**: All file readers and module resolvers enforce lexical and canonical realpath checks (`Path.resolve()`), rejecting any relative path or symbolic link that attempts to traverse outside the target project root directory.

---

## 3. Third-Party Network Interactions and Offline Mode

- **MCP Daemon Transport**: `astermesh serve` defaults to `stdio` transport or binds to local loopback (`127.0.0.1`) when SSE mode is explicitly selected. Users should not bind SSE transport to public network interfaces (`0.0.0.0`) without external authentication and TLS encryption.
- **Interactive HTML Visualization (`astermesh_view.html`)**: When `astermesh build` generates the optional `astermesh_view.html` file via `pyvis`, opening that HTML file in a web browser loads client-side `vis-network` rendering scripts from a public CDN (`cdn_resources="remote"`). Users operating in air-gapped environments or requiring zero browser requests to external CDNs should pass the `--no-html` flag (`astermesh build . --no-html`).

---

## 4. Data Subject Rights and Artifact Erasure

All files generated by Astermesh (`astermesh-graph/context_graph.acn`, `astermesh-graph/GRAPH_REPORT.md`, `astermesh-graph/astermesh_view.html`) are written solely to the local output directory specified by the user:

- **Right of Access and Rectification**: Users have full local filesystem ownership to inspect, modify, or audit all generated text and graph artifacts.
- **Right to Erasure**: Stopping the `astermesh serve` process immediately clears the in-memory graph from RAM, and deleting the local `astermesh-graph/` directory permanently erases all generated artifacts.
